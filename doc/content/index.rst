Sacrifice to Sphinx
===================

Description
===========
Markdown support for OTOBO web services.

The package adds the core module ``Kernel::System::Markdown``, which converts Markdown to HTML and HTML to Markdown,
and integrates it into the generic interface:

- **Inbound (ticket operations):** The operations ``TicketCreate`` and ``TicketUpdate`` accept articles with the
  MIME type ``text/markdown``. The body is converted to HTML before the article is created, so the article is stored
  and displayed like any other HTML article.
- **Outbound (ticket invokers):** The invokers ``Ticket::TicketCreate`` and ``Ticket::TicketUpdate`` can convert the
  HTML body of an article to Markdown before the request is sent to the remote system, e.g. to create an issue
  comment on GitHub.

Markdown support in the agent and customer frontend is not part of this package.

System requirements
===================

Framework
---------
OTOBO 11.1.x

Packages
--------
\-

Third-party software
--------------------
The following CPAN modules are required. Both are pure Perl modules and can be installed with ``cpanm``:

- ``Markdown::Perl`` (Markdown to HTML, CommonMark with the GitHub extensions tables, task lists, strikethrough and autolinks)
- ``HTML::TreeBuilder`` from the distribution ``HTML-Tree`` (HTML parsing for the conversion from HTML to Markdown)

.. code-block:: bash

    cpanm Markdown::Perl HTML::Tree

Usage
=====

Setup
-----
Install the package via the package manager. The package overrides the following framework files via the
``Custom`` directory, so no other installed package may ship the same files:

- ``Kernel/GenericInterface/Invoker/Ticket/Common.pm`` (includes the extension of the package DynamicFieldAttachment
  for attachment dynamic fields)
- ``Kernel/GenericInterface/Operation/Ticket/Common.pm``
- ``Kernel/GenericInterface/Operation/Ticket/TicketCreate.pm``
- ``Kernel/GenericInterface/Operation/Ticket/TicketUpdate.pm``

Inbound: Markdown articles via TicketCreate and TicketUpdate
------------------------------------------------------------
Pass the article with the MIME type ``text/markdown``, either in ``MimeType`` or in ``ContentType``:

.. code-block:: json

    {
        "Ticket": { "Title": "From GitHub", "Queue": "Raw", "State": "new", "Priority": "3 normal", "CustomerUser": "customer@example.com" },
        "Article": {
            "Subject": "Issue #123",
            "Body": "# Heading\n\nSome **bold** text and a [link](https://otobo.io/).\n\n- [ ] open task",
            "ContentType": "text/markdown; charset=utf8"
        }
    }

The body is converted with the GitHub flavoured Markdown dialect. Raw HTML in the Markdown is cleaned with
``Kernel::System::HTMLUtils::Safety()``, so scripts, ``javascript:`` links and event handlers are removed.
The article is stored with the MIME type ``text/html``. The charset part of the content type is kept.

When the CPAN module ``Markdown::Perl`` is not installed, the request is answered with the error code
``TicketCreate.MarkdownConversionFailed`` or ``TicketUpdate.MarkdownConversionFailed`` and nothing is written.

Outbound: Markdown articles via the ticket invokers
---------------------------------------------------
Set the option ``ConvertArticleBodyToMarkdown`` in the configuration of the invoker. The option is not available
in the invoker administration dialog, so it has to be added via the YAML configuration of the web service:

.. code-block:: yaml

    Requester:
      Invoker:
        GitHubIssueComment:
          Type: Ticket::TicketCreate
          ConvertArticleBodyToMarkdown: 1
          RequestArticleFields:
            - Body
            - ContentType
            - MimeType
            - Charset
            - Subject

OTOBO stores the body of HTML articles as plain text and keeps the HTML version as the attachment ``file-2``.
With the option set, the invoker takes the HTML body from that attachment, converts it to Markdown and passes it
on in the field ``Body`` with the MIME type ``text/markdown``. Articles without an HTML body, e.g. plain text
emails, are passed on unchanged, as plain text is valid Markdown.

The conversion supports headings, paragraphs, line breaks, bold, italic, strikethrough, inline code, code blocks
(with the language from a ``language-*`` class as generated by the rich text editor), links, images, nested lists,
block quotes, horizontal rules and tables. Tables become pipe tables, so the content of a cell is reduced to a
single line. Inline images (``data:`` URLs) are replaced by their alternative text. All other elements are
replaced by their text content.

Using the module in own code
----------------------------
.. code-block:: perl

    my $MarkdownObject = $Kernel::OM->Get('Kernel::System::Markdown');

    my $HTML     = $MarkdownObject->ToHTML( String => $Markdown );      # undef when Markdown::Perl is missing
    my $Markdown = $MarkdownObject->FromHTML( String => $HTML );        # undef when HTML::TreeBuilder is missing

    my $Available = $MarkdownObject->IsAvailable( Direction => 'ToHTML' );    # or 'FromHTML'

Configuration Reference
-----------------------
The package has no system configuration settings.

Unit tests
==========
- ``scripts/test/Markdown/ToHTML.t`` and ``scripts/test/Markdown/FromHTML.t`` test the conversions.
- ``scripts/test/GenericInterface/Invoker/Ticket/MarkdownBody.t`` tests the invoker option ``ConvertArticleBodyToMarkdown``.

The tests are skipped when the required CPAN modules are not installed.
